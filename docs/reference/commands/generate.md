# muxt generate

Writes `template_routes.go`: one `http.Handler` per route template, the `RoutesReceiver` interface those handlers call, `TemplateData`, `TemplateRoutePaths`, `TemplateRoute`, `TemplateRouteBuilder`, and, when a route uses `sse`, `SSETemplateData`.

```bash
muxt generate --use-receiver-type=Server
```

It prints nothing unless it has a note or a warning, which go to stdout. Parameter and result types come from `--use-receiver-type` ([type resolution](../call-parameters.md#type-resolution)). Flags: [cli.md](../cli.md#flags). `-v` prints each handler as it is generated and each file written (`wrote template_routes.go: 3 routes`).

The `go:generate` form, next to the [templates variable](../templates-variable.md):

```go
//go:generate go run github.com/typelate/muxt generate --use-receiver-type=Server
```

## muxt.json

With no flags, `generate` reads [`muxt.json`](../muxt-json.md): in the file's directory it writes every entry, elsewhere the directory's entry. In a directory an entry configures, a flag is rejected and nothing is written; `-v` and `-C` are accepted:

```text
Error: configure generate with fields in /home/me/app/muxt.json instead of flags: --output-htmx (output_htmx)
```

| Sub-command | Aliases | Does | Flags |
|---|---|---|---|
| `config` | `configuration` | Write an empty `muxt.json` in the working directory; fails if one exists. | none |
| `package NAME` | | Create the package directory and its entry ([below](#generate-package)). | the `generate` flags, stored in the entry |
| `def NAME` | `definition` | Add a route template named `NAME` to a template file. Without `--output-file` it prints a txtar archive of the files it would write and changes nothing. The method stub it prints is a placeholder to rewrite: its result type is `any`, and its body and receiver form follow what muxt infers. Imports are not added. | `--output-file`, `--output-document`, `--output-fragment`, `--use-receiver-type` |

Steps: [move generate flags into muxt.json](../../how-to/muxt-json.md).

### generate package

`generate package NAME` writes `NAME/NAME.go` (the `go:embed`, the templates variable under its configured name, and the receiver type), an empty `NAME/NAME.gohtml`, and the entry in `muxt.json`. The entry records `use_receiver_type` unless `package_defaults` supplies one. `NAME` is one Go identifier that is not `main` and does not start with `_`, which the go command ignores in a file name.

## Files

`--output-multiple-files` writes `template_routes.go` plus one `<name>_template_routes_gen.go` per `.gohtml` file ([reference_cleanup_switch_to_multiple_files.txt](../../../cmd/muxt/testdata/reference_cleanup_switch_to_multiple_files.txt)).

Each generated file opens with `// Code generated by muxt generate` and the flags that produced it. A run deletes any such file with the current `--output-routes-func` that it did not rewrite, so renaming a template or switching file modes leaves nothing behind.

muxt replaces each file through a temporary file renamed into place, and a failed run restores what it replaced in that package. A run over several `muxt.json` entries leaves the packages it already wrote as written.

## Version header

A generated file records the muxt version in a `// muxt version:` line and in the `MuxtVersion` method. A tagged build (`v0.21.0`, `v0.21.0-dev.2`) always records its own version. A build with no tag (`(devel)`, a pseudo-version such as `v0.20.2-0.20260912101010-0123456789ab`, or a `+dirty` build) keeps the version the existing output file already records, so a local `go generate` does not rewrite the line that CI wrote. When there is no existing file, it records its own version, such as `(devel)` ([reference_version_header_stable.txt](../../../cmd/muxt/testdata/reference_version_header_stable.txt)). `--output-muxt-version=false` omits both.

## Routes function

```go
func TemplateRoutes(mux *http.ServeMux, receiver RoutesReceiver) TemplateRoutePaths
```

`TemplateRoutes` only adds handlers to `mux`. Register what no template renders (files, hand-written JSON, health checks) on the same mux; for a directory of CSS and other files, see [Static assets](#static-assets):

```go
mux.Handle("GET /styles.css", http.FileServerFS(staticFS))
TemplateRoutes(mux, srv)
```

Each `--output-routes-func-with-*-param` flag appends a parameter. With all three the order is `logger`, `pathsPrefix`, `middleware` ([reference_cli_middleware_flag_combined.txt](../../../cmd/muxt/testdata/reference_cli_middleware_flag_combined.txt)).

| Parameter | Effect |
|---|---|
| `logger *slog.Logger` | HTML and `marshalJSON` routes log `handling request` at `DEBUG` with `pattern`, `path`, `method`, and a failed render at `ERROR` (`failed to render page`) with `pattern`, `path`, `error`. Tutorial: [Add Logging](../../tutorials/add-logging.md). |
| `pathsPrefix string` | Joined onto every pattern registered on the mux and every path `TemplateRoutePaths` builds. |
| `middleware func(next http.Handler) http.Handler` | Each handler is registered as `middleware(http.HandlerFunc(handler))`. `nil` registers handlers unwrapped. |

## Static assets

`--input-static-assets-directory=<dir>` and `--output-static-assets-path=<path>` serve one directory of the templates package under one URL path. Both are required together, and a run takes one mapping.

```bash
muxt generate --input-static-assets-directory=assets --output-static-assets-path=/static
```

The routes file embeds the directory, in a variable named after the routes function:

```go
//go:embed assets
var templateRoutesStaticAssets embed.FS
```

and `TemplateRoutes` serves it after the template routes:

```go
staticAssets, err := fs.Sub(templateRoutesStaticAssets, "assets")
if err != nil {
	panic(fmt.Errorf("muxt: static assets directory %q: %w", "assets", err))
}
mux.Handle("GET /static/", http.StripPrefix("/static/", http.HandlerFunc(func(response http.ResponseWriter, request *http.Request) {
	name := strings.TrimPrefix(path.Clean("/"+request.URL.Path), "/")
	if name == "" {
		name = "."
	}
	if !fs.ValidPath(name) {
		http.NotFound(response, request)
		return
	}
	if _, err := fs.ReadDir(staticAssets, name); err == nil {
		if _, err := fs.Stat(staticAssets, path.Join(name, "index.html")); err != nil {
			http.NotFound(response, request)
			return
		}
	}
	http.FileServerFS(staticAssets).ServeHTTP(response, request)
})))
```

The pattern is always `GET`, and the path gets a trailing `/`. A request for a directory, the static assets path itself or a subdirectory, is a 404 unless the directory holds an `index.html`, which is served as `http.FileServerFS` serves it; the files are never listed ([reference_static_assets_no_listing.txt](../../../cmd/muxt/testdata/reference_static_assets_no_listing.txt)).

`TemplateRoutePaths` gains a method returning the path, named like a call-less `GET` route with that path ([route methods](../call-results.md#route-methods)): `/static` is `ReadStatic`, so a template links `{{.Path.ReadStatic}}app.css` ([reference_static_assets.txt](../../../cmd/muxt/testdata/reference_static_assets.txt)).

The generated file's [header](#files) records both flags, which is why a project that serves its CSS by hand gets less from [`muxt fmt`](fmt.md#migrating-a-project). `muxt fmt` reads them back to find the CSS a template uses ([where CSS comes from](fmt.md#where-css-comes-from)).

`generate` rejects:

- one flag without the other ([err_static_assets_one_flag.txt](../../../cmd/muxt/testdata/err_static_assets_one_flag.txt));
- a path not starting with `/`, the path `/` ([err_static_assets_path.txt](../../../cmd/muxt/testdata/err_static_assets_path.txt)), or a path with a wildcard or an empty segment;
- a directory that is absolute, contains `..` or `\`, or is not a slash-separated path inside the package;
- a value containing whitespace;
- a directory that does not exist ([err_static_assets_directory.txt](../../../cmd/muxt/testdata/err_static_assets_directory.txt)), is a symbolic link, is not a directory, or holds no file `go:embed` would include;
- a template registering `GET <path>/` ([err_static_assets_collision.txt](../../../cmd/muxt/testdata/err_static_assets_collision.txt)), one registering `GET <path>/{name...}`, which matches the same requests ([err_static_assets_wildcard_conflict.txt](../../../cmd/muxt/testdata/err_static_assets_wildcard_conflict.txt)), or one whose path method has the static assets path method's name.

## Edge cases

- **Files from another route set.** A run keeps generated files whose routes function name is not the current `--output-routes-func` ([several route sets can share a package](../../how-to/multiple-route-sets.md)); remove those by hand.
- **Symlinked generated files.** A generated file that is a symlink is written through to its target, unless the target is an absolute path or outside the package directory; then generation fails.
- **The version after an untagged build.** After an untagged build regenerates a file, `MuxtVersion()` and `explore-module` report the last tagged version that wrote it, not the muxt that actually ran.
- **Registration order.** The mux serves the most specific pattern whatever the registration order. Registering a pattern a template also declares panics.
- **SSE route logging.** SSE routes log only errors: a failed render and a method error (`sse handler returned an error`). Without the `logger` parameter, those errors go to `slog.ErrorContext` on the default logger.
- **Names starting with `.` or `_`.** `go:embed` leaves them out, so those files are not served from the static assets directory.
- **Static assets with `pathsPrefix` or `middleware`.** The static assets pattern and the prefix `http.StripPrefix` strips are both joined onto `pathsPrefix`, and `middleware` wraps the static assets handler like any other ([reference_static_assets_path_prefix.txt](../../../cmd/muxt/testdata/reference_static_assets_path_prefix.txt)).

## Warnings

A method taking `response` sets its own status code and headers, so muxt sets neither and warns once per route ([reference_response_argument_warning.txt](../../../cmd/muxt/testdata/reference_response_argument_warning.txt)). The template is still written after the method returns. `MUXT_SILENCE_WARNING_HTTP_RESPONSE_ARGUMENT=true` silences the warning.
