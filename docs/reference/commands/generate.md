# muxt generate

Writes `template_routes.go`: one `http.Handler` per route template, the `RoutesReceiver` interface those handlers call, `TemplateData`, `TemplateRoutePaths`, `TemplateRoute`, `TemplateRouteBuilder`, and, when a route uses `sse`, `SSETemplateData`.

```bash
muxt generate --use-receiver-type=Server
```

```text
wrote template_routes.go: 3 routes
```

Parameter and result types come from `--use-receiver-type` ([type resolution](../call-parameters.md#type-resolution)). Flags: [cli.md](../cli.md#flags). `-v` prints each handler as it is generated.

The `go:generate` form, next to the [templates variable](../templates-variable.md):

```go
//go:generate go run github.com/typelate/muxt generate --use-receiver-type=Server
```

## Files

`--output-multiple-files` writes `template_routes.go` plus one `<name>_template_routes_gen.go` per `.gohtml` file ([reference_cleanup_switch_to_multiple_files.txt](../../../cmd/muxt/testdata/reference_cleanup_switch_to_multiple_files.txt)).

Each generated file opens with `// Code generated by muxt generate` and the flags that produced it. A run deletes any such file with the current `--output-routes-func` that it did not rewrite, so renaming a template or switching file modes leaves nothing behind. Files with another routes function name are kept ([several route sets can share a package](../../how-to/multiple-route-sets.md)); remove those by hand.

Each file is replaced through a temporary file renamed into place, and a failed run puts back what it replaced. A generated file that is a symlink is written through to its target, unless the target is an absolute path or outside the package directory; then generation fails.

## Routes function

```go
func TemplateRoutes(mux *http.ServeMux, receiver RoutesReceiver) TemplateRoutePaths
```

`TemplateRoutes` only adds handlers to `mux`. Register what a template should not render (CSS, files, hand-written JSON, health checks) on the same mux:

```go
mux.Handle("GET /styles.css", http.FileServerFS(staticFS))
TemplateRoutes(mux, srv)
```

The mux serves the most specific pattern whatever the registration order; registering a pattern a template also declares panics.

Each `--output-routes-func-with-*-param` flag appends a parameter. With all three the order is `logger`, `pathsPrefix`, `middleware` ([reference_cli_middleware_flag_combined.txt](../../../cmd/muxt/testdata/reference_cli_middleware_flag_combined.txt)).

| Parameter | Effect |
|---|---|
| `logger *slog.Logger` | HTML and `marshalJSON` routes log `handling request` at `DEBUG` with `pattern`, `path`, `method`, and a failed render at `ERROR` (`failed to render page`) with `pattern`, `path`, `error`. SSE routes log only errors: a failed render and a method error (`sse handler returned an error`). Without the flag, those errors go to `slog.ErrorContext` on the default logger. Tutorial: [Add Logging](../../tutorials/add-logging.md). |
| `pathsPrefix string` | Joined onto every pattern registered on the mux and every path `TemplateRoutePaths` builds. |
| `middleware func(next http.Handler) http.Handler` | Each handler is registered as `middleware(http.HandlerFunc(handler))`. `nil` registers handlers unwrapped. |

## Warnings

A method taking `response` sets its own status code and headers, so muxt sets neither and warns once per route ([reference_response_argument_warning.txt](../../../cmd/muxt/testdata/reference_response_argument_warning.txt)). The template is still written after the method returns. `MUXT_SILENCE_WARNING_HTTP_RESPONSE_ARGUMENT=true` silences the warning.
